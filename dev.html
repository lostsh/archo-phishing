Le bon réflexe Édition développeurs

Planche 00, édition développeurs

Pas besoin de tout auditer. Juste de t’arrêter au bon moment.

Installer, cloner, coller une commande : c’est ton quotidien, et ça se fait en pilote auto. Les attaquants l’ont compris. Ils ne cherchent plus seulement ton mot de passe : ils veulent que tu exécutes leur code, avec tes droits, sur ton poste.

01

Le principe

  1. Phase 1

    Pilote auto

    npm install, git clone, un bout de code copié depuis la doc : tu le fais cent fois par jour sans y penser. C’est normal.

  2. Phase 2

    Un signal

    Quelque chose te pousse à exécuter, installer ou autoriser, en dehors de ton flux habituel.

  3. Phase 3

    Mode manuel

    Trente secondes : d’où vient ce code, et qu’est-ce qu’il va faire ?

  4. Phase 4

    Retour au pilote auto

    Vérifié ? Tu continues. Douteux ? Tu signales, et tu continues.

02

Le signal : exécuter, hors contexte

Du code malveillant ressemble à du code légitime : même syntaxe, même commande d’installation, parfois le vrai nom du projet à une lettre près. Ce qui le trahit, c’est le contexte : quelqu’un veut que tu exécutes quelque chose, maintenant.

On te demande de…

  • coller une commande dans un terminal ou dans Exécuter
  • lancer un curl … | bash ou un installeur
  • installer un paquet, une extension, une dépendance
  • autoriser une app OAuth ou entrer un code d’appareil

Et le contexte cloche…

  • une page web qui veut passer par ton terminal
  • un domaine presque juste
  • une urgence : « ton token expire aujourd’hui »
  • un inconnu : recruteur, contributeur, issue sortie de nulle part

Exécuter, plus un contexte inattendu : tu passes en manuel.

Dans le doute, une seule question : est-ce que j’ai moi-même décidé d’exécuter ça, depuis une source que je connais ?

03

En manuel : trois gestes

  1. 1

    Stop

    Ne colle rien, n’exécute rien. Une page web n’a jamais besoin de ton terminal pour vérifier que tu es humain.

  2. 2

    Lis avant d’exécuter

    Récupère la commande sur la doc officielle, en tapant le domaine toi-même. Pour un script, télécharge-le, lis-le, puis décide.

  3. 3

    Relâche

    Légitime ? Installe et continue. Douteux ? Signale-le à l’équipe sécurité avec l’URL, la commande ou le paquet.

04

Les pièges à connaître

  • Le faux CAPTCHA qui te fait coller une commande

    « Appuie sur Win + R, puis Ctrl + V, puis Entrée », ou « colle ceci dans ton Terminal » : c’est ClickFix. La page a déjà copié la commande dans ton presse-papiers.

  • curl | bash depuis un domaine presque juste

    Le format est légitime, c’est le domaine qui ment. De fausses annonces ont déjà imité la page d’installation de Homebrew. Vérifie le domaine caractère par caractère.

  • Un paquet au nom presque juste

    Typosquatting, ou nom inventé par une IA puis enregistré par un attaquant. Avant d’installer : éditeur, âge du paquet, nombre de téléchargements.

  • npm install exécute du code

    Les scripts preinstall et postinstall tournent avec tes droits. Pour un dépôt inconnu : --ignore-scripts, ou un conteneur jetable.

  • Le test technique d’un recruteur

    « Clone ce projet et lance-le » : technique connue pour infecter les postes de développeurs. Lance-le dans une VM ou un conteneur, jamais sur ta machine de travail.

  • Le mail « mets à jour ta 2FA npm »

    En 2025, un faux domaine de support npm a suffi pour prendre le compte d’un mainteneur de paquets très utilisés. Tokens et 2FA se gèrent sur le site officiel, jamais via un lien.

  • Un code d’appareil que tu n’as pas demandé

    Le phishing par code d’appareil passe par la vraie page de connexion. Si tu n’as pas lancé la connexion, n’entre pas le code. Pareil pour une app OAuth qui veut tes dépôts.

  • Extensions et GitHub Actions : du code tiers

    Des Actions populaires ont déjà été compromises. Épingle-les par SHA de commit, et vérifie l’éditeur d’une extension avant de l’installer.

05

Ce que tu risques, toi

  • Tes secrets

    Clés SSH, tokens, fichiers .env, cookies de session : volés en quelques secondes.

  • Tes comptes

    GitHub, npm, cloud, gestionnaire de mots de passe : tout ce qui est ouvert sur ton poste.

  • Ton nom sur du code piégé

    Ton compte publie une version malveillante, et d’autres l’installent en te faisant confiance.

  • Tes collègues

    Depuis ton poste, l’attaquant rebondit sur les dépôts, la CI, puis le reste.

  • Ta machine, enrôlée

    Recrutée dans un réseau de machines piratées pour attaquer hôpitaux, services publics ou entreprises.

  • Ton temps

    Tous les secrets à renouveler, le poste à réinstaller, et le stress qui va avec.

06

Tu as exécuté ? Agis vite, sans honte

  1. Coupe le réseau de la machine, sans l’éteindre.

  2. Préviens l’équipe sécurité tout de suite, avec la commande, l’URL ou le paquet en cause.

  3. Renouvelle tes secrets depuis une autre machine : tokens, clés SSH, sessions.

  4. Ne nettoie pas toi-même : supprimer des fichiers efface les traces dont l’équipe a besoin.

Personne ne te reprochera d’avoir collé une commande. Ce qui coûte cher, c’est de te taire.

Un doute sur une commande ou un paquet ? Envoie-le à l’équipe sécurité avant de l’exécuter.
